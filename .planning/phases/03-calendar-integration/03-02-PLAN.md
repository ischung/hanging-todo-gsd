2) Add a single delegated click listener attached to `calendarSection` (place it after the existing listContainer listeners, before the `function startEdit` block). Use this exact code:

```js
// 위임: 캘린더 nav 버튼 + 셀 선택 (단일 listener — Phase 2 패턴 동일).
// 인접달 셀(<div>)은 data-key/data-action 둘 다 없어 자연스럽게 no-op.
calendarSection.addEventListener('click', (e) => {
  const t = e.target;
  if (!(t instanceof HTMLElement)) return;

  const navBtn = t.closest('[data-action]');
  if (navBtn) {
    const a = navBtn.dataset.action;
    if (a === 'prev') viewYM = prevMonth(viewYM);
    else if (a === 'next') viewYM = nextMonth(viewYM);
    else if (a === 'today') {
      viewYM = todayYM();
      selectedKey = dateKey();
    }
    render();
    return;
  }

  const cell = t.closest('[data-key]');
  if (cell) {
    selectedKey = cell.dataset.key;
    render();
    return;
  }
  // else: adjacent-month div or whitespace — no-op (decision E lock).
});
```

Important details:
- `closest('[data-action]')` is checked BEFORE `closest('[data-key]')` because the two attribute namespaces are mutually exclusive on any one element subtree, but checking nav first is the cheaper / more specific match.
- `viewYM` is intentionally NOT reset on cell click — Pitfall 5 (selectedKey preserved across nav).
- `selectedKey = cell.dataset.key` reads a string from a sanitized-by-construction attribute (codomain `\d{4}-\d{2}-\d{2}`); no parsing or eval.
- No `commit()` is called in this handler — selectedKey/viewYM are pure UI state and must not flow into save().
